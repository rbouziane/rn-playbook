# i18n

Structure des clés, fichiers de traduction, pluriel, variables.

---

## i18n

### Règles d'usage

- **Toujours via `translate()`**, jamais de string littérale dans le JSX
- Variables passées en deuxième argument : `translate('hello.user', { name: 'Ronan' })`
- Clés en **camelCase** (cohérent avec le reste du code)
- **Toute clé ajoutée l'est dans TOUTES les locales** (`fr.json` **et** `en.json`…), même structure, même moment — jamais de clé orpheline dans une seule langue
- Les labels d'accessibilité (`accessibilityLabel`) sont des strings visibles : ils passent aussi par `translate()`

```ts
import { translate } from '~i18n/translate';

translate('common.confirm');
translate('item.itemDetailTitle');
translate('hello.user', { name: props.userName });
```

### Localisation des fichiers

Un fichier par locale à la racine :

```
app/i18n/
├── translate.ts
├── fr.json
└── en.json
```

### Structure des clés

Hiérarchie standard à trois familles :

```json
{
  "common": {
    "confirm": "Valider",
    "cancel": "Annuler",
    "loading": "Chargement…",
    "retry": "Réessayer"
  },
  "error": {
    "network": "Pas de connexion internet",
    "item": {
      "notFound": "Article introuvable",
      "update": "Impossible de mettre à jour l'article"
    },
    "auth": {
      "invalidCredentials": "Identifiants invalides"
    }
  },
  "success": {
    "item": {
      "created": "Article créé",
      "updated": "Article mis à jour"
    }
  },
  "item": {
    "itemsTitle": "Mes articles",
    "itemDetailTitle": "Détail de l'article",
    "itemDetailDescription": "{count} variantes disponibles"
  },
  "auth": {
    "loginTitle": "Connexion",
    "loginButton": "Se connecter"
  }
}
```

**Familles transverses** (utilisables depuis n'importe quelle feature) :

- `common.*` — labels génériques (boutons, états, actions communes), à plat
- `error.[domaine].[clé]` — messages d'erreur scopés par domaine
- `success.[domaine].[clé]` — messages de succès scopés par domaine

**Familles métier** (une par feature) :

- `[feature].[clé]` — toutes les clés propres à une feature, à plat sous son namespace

### Variables

Référencer avec `{name}` dans la valeur, passer un objet en deuxième argument :

```json
{
  "hello": {
    "user": "Bonjour {name}"
  }
}
```

```ts
translate('hello.user', { name: props.userName });
```

`i18n-js` n'interpole `{name}` qu'à condition de le lui dire : son motif par défaut ne reconnaît que `%{name}` et `{{name}}`, et une variable non reconnue **ressort littéralement dans l'UI**, sans erreur. La syntaxe à une accolade se branche une fois, dans `translate.ts` :

```ts
i18n.placeholder = /\{([\w.]+)\}/g;
```

### Pluriel

`i18n-js` **ne parle pas ICU** : une chaîne `{count, plural, …}` est renvoyée telle quelle, à l'écran. Le pluriel passe par le mécanisme natif de la lib — une clé par forme, sous la clé de base :

```json
{
  "item": {
    "count": {
      "zero": "Aucun article",
      "one": "{count} article",
      "other": "{count} articles"
    }
  }
}
```

```ts
translate('item.count', { count: items.length });
```

`i18n-js` choisit la forme à partir de `count` et des règles de la locale. Les formes disponibles varient selon la langue (`one`/`other` en anglais, `one`/`few`/`many`/`other` en polonais…) : `other` est **obligatoire**, c'est le repli.
